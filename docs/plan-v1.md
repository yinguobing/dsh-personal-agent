# 个人版 Super-agent 计划 v1

状态：草案（2026-11-07）
依据：`deepseek-ai/dsh-superagent-prototype`（MIT，12,390 行 TS，2026-10-31 首版，至今未更新）

## 0. 一句话

把原型的调度内核，改造成一个"只说话、不折腾"的个人助理：**一个入口、一件事、一条每日摘要。**

## 1. 这一版做什么、不做什么

做：

- 自托管、单用户
- 首个场景：内容与写作（博客 / B 站）
- 入口：微信 1:1（已打通）+ Web
- 默认 `observe`：先只看它想做什么，不真对外

不做（本版明确排除）：

- 多租户、托管服务、账号体系
- 移动 App
- 自动对外发布、自动回复评论
- GitHub 编码流程（原型自带的这条线不保留为默认）

## 2. 为什么 fork，而不是依赖或重写

- 原型 `private: true`，未发布 npm，无法作为依赖引用
- 内核与 GitHub 已解耦，但 bundle 仍是单体包，拆包收益 < 成本
- 重写内核要重新踩一遍 Trigger 幂等、Thread 归并、崩溃恢复的坑，不值得

结论：fork 一份，保留 MIT 声明与来源说明，改上层。

## 3. 复用边界

保留：

- `src/core/`：engine、tickets、evals、outbox、policy 接口、幂等与恢复
- Source 适配器模式（`ports.ts` 的 `Source` / `Policy` / `Executor` / `Outbox` 全是接口）
- Worker Session 隔离执行
- `observe` 模式与授权分层

替换：

- `src/sources/github*` → 个人数据源
- `prompts/` 路由提示词（现在通篇是"一个 GitHub 仓库的编码 agent"）
- `src/client/` 运维面板 → 聊天里的每日摘要
- `SETUP.md` 的安装流程（仍要求终端、`gh` 登录）

新增：

- 手动 Source（用户自己发来的消息，最小可用入口）
- 内容场景的交付物定义
- 自然语言规则

## 4. 产品形态

- **入口**：微信 1:1 为主，Web 为辅。用户在哪儿说话，结果回哪儿。
- **核心对象**：事。用户可见的词只有"事"，不出现 session / ticket / source / policy。
- **每件事只有四种状态**：
  - 等我（缺信息 / 缺决定）
  - 它在做
  - 等我拍板（有草稿了）
  - 完了
- **每日一条摘要**，最多三条，按"需要你"排序。没事就不发。
- **说话风格**：一句话说清三件事——这是什么、为什么找你、你可以回什么。

## 5. 易用性硬指标（可验收，不是形容词）

1. 首次可用 ≤ 10 分钟；终局目标全程不碰终端（P0 阶段允许终端，P1 起收敛）
2. 用户词汇表里没有 session / ticket / source / policy
3. 任何主动消息都能回答"为什么找我"，且能一句话撤回
4. 断网、重启、token 过期后自动恢复，不丢事、不重复问
5. 一条消息只问一个问题
6. 沉默是默认：没有需要人的事就不发
7. 所有对外动作先出草稿，人点头才发

## 6. MVP：内容与写作

真实流程：

```
灵感 / 链接 → 素材 → 初稿 → 他改 → 发布 → 回填
```

P1 只做前三段和最后一段的"留痕"：

- 一个"稿子"对象，跨天存活
- 素材自动归档（链接、截图、摘录）
- 初稿落到文件，微信里给一段摘要 + 待定的两三处
- 发布后回填链接与时间，供以后追问

不做：自动发布、自动回评、数据抓取。

## 7. 里程碑

| 阶段 | 内容 | 预估 |
|---|---|---|
| P0 骨架 | fork、改名、去掉 GitHub 默认源、加 manual source；跑通"我说一句 → 开一件事 → worker 干活 → 回我" | 1 周 |
| P1 入口 | 微信接入、每日摘要、事的状态查询 | 1 周 |
| P2 场景 | 内容流水线跑通一篇真实文章 | 2 周 |
| P3 主动 | 自然语言规则 + observe 报告 | 1–2 周 |
| P4 泛化 | 第二个场景验证抽象是否成立 | 待定 |

每个里程碑只加一个能力，加完先自己用一周再进下一个。

## 8. 为产品化预留的四个决定

现在只服务一个人，但下面四件事从第一天就按多用户写，成本几乎为零：

1. **Owner / Principal 概念存在**，哪怕永远只有一个
2. **状态目录按 owner 分区**，代码里不写死绝对路径
3. **Source 是实例**（配置 + 凭据），可增删，不是全局单例
4. **交付通道抽象成 Channel**，微信只是其中一个实现

反过来，明确不提前做的：计费、配额、审计导出、权限继承。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 主动变成噪音 | 默认 observe，先跑一周看"本来会做什么" |
| 和现有小白打架 | P0 起用独立 profile 与独立状态目录，不碰线上 |
| 上游冻结、无法跟进 | 不追同步；保留 git 历史，需要时手工 diff |
| 范围膨胀 | 每个里程碑只加一个能力，加完先自用一周 |
| "普通人"想象错位 | 第一个用户就是自己；每个决定问"这个我明天会用吗" |
