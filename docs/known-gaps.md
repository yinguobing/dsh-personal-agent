# 哪里还不牢

按「会不会咬人」排序，不按工作量。每一条都写清楚：现在是什么状态、凭什么这么说、真出问题会怎样。

## 0. 长期记忆是补上的，不是原生的

**状态**：默认安装会带上 `dsh-memory-index`（工作区 = 状态目录的 `MEMORY.md` 与 `memory/`），主会话与 worker 都能用
`memory_search` / `memory_read` / `memory_write`。

**凭什么**：验证方式是「说一件要记住的事 → 删掉 DSH 会话记录 → 重启 → 问它」。详见 `docs/memory.md`。

**会怎样**：这是外挂，不是内核能力。它记的是**你写进去的东西**，不会自动从对话里挑事实；autoRecall 只把
`MEMORY.md`、今天与昨天注入系统提示，旧的要靠搜索。

## 0.5 简单视图只做了第一刀

**状态**：侧栏默认打开的是简单首页（对话 + 我在办的事 + 我想做的），工程师的六个标签在「高级视图」后面。

**还没做**：点开一条事，进的仍是工程师视图的票据详情（授权依据、输入、报告、时间线）；设置页仍是六组工程配置。

**会怎样**：普通人能看懂首页，但点进详情就掉回机器视角。人话详情与精简设置是下一刀。

## 1. 真实微信没验过

**状态**：只用本地 iLink 替身跑通过，没有用真实机器人账号扫码收发。

**凭什么**：替身实现了 `ilink/bot/getupdates` 与 `ilink/bot/sendmessage` 的协议形状，消息与回包都按真实字段构造；客户端实现参照了线上小白在用的 `dsh-channel-weixin`。

**会怎样**：协议里的字段（比如 context_token 的失效时机、限流、消息类型）可能与替身不同。真出问题，表现是「微信收不到」或「发出去但对方没收到」。

**怎么补**：`dsh-weixin-login` 扫一次码，走一遍「发消息 → 提问 → 回答 → 结果」。

## 2. 并发只测了两条

**状态**：验证过「连发两条独立请求 → 两张票」和「一张票提问后回答 → 续原票」。

**没测**：三张以上同时打开的票；两张票同时等人回答（此时回答会进入最近提问的那张）；worker 与摘要同时抢占主会话。

**会怎样**：极端情况下回答可能落到错误的票上。

## 3. 摘要的静默只验过一次

**状态**：验过「有事就发一条」和「重启不重发」。

**没验**：那一小时确实没事时是否真的不发（逻辑上是，但没有观测记录）；跨时区/夏令时下的 `digestHour`。

## 4. 面板对话只显示最近 12 轮

**状态**：没有翻页，没有流式输出，4 秒轮询。

**会怎样**：长对话看不到早期内容；回复是整段出现，不是逐字。

## 5. 追问已完成的票会开新票

**状态**：这是第二十四轮改的线程模型带来的：没有票在等回答时，每条消息都是新线程。

**会怎样**：对一张已完成的票说「把刚才那篇的标题改一下」，会开一张新票，而不是续在原票上。工人能从上下文找到文件（同一票据目录不同），但不是原来那张。

**为什么这样**：另一条路（共用线程）会让新请求被旧票吞掉，那个 bug 更严重。

## 6. 失败通知只说「刚才那条」

**状态**：回合失败时，往最后一条渠道消息所在的会话发一条「刚才那条消息没能处理完」。

**会怎样**：连发几条、其中一条失败时，可能指错是哪条。

## 7. 提示词有字符预算

**状态**：worker 提示词有 4 万字符上限的守卫，加内容规则时要先删旧的。

**会怎样**：不是运行时风险，是维护风险——以后想加规则，得先想清楚删什么。

## 8. 英文文案是翻译的，不是写出来的

**状态**：中文是主要语言，英文文案由同一批键翻译而来，没有母语者过一遍。

**会怎样**：术语与语气可能不自然，尤其在意图说明上。

## 已经修掉、但值得记住的坑

- **worker 没有 GitHub 账号时起不来**：工具描述里提前读了账号信息。
- **worker 问完不停**：报告带问题后没有挂起，继续搜网页。
- **批准被吞**：批准走对话线程，被无关的旧票接走。
- **新请求被旧票接走**：一条对话一个线程的必然结果。
- **缺密钥时静默**：失败只写在会话事件里，界面看不见。
