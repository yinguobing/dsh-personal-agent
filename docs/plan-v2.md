# 两层架构（v2）

结论：**搭档 = 一个对话 agent + 一个任务服务。** 不需要中台。

## 为什么

super agent 原型把“事务性工作”交给了模型：消息被包成候选卡注入主会话，由主会话（router）
读取、判断、建票、跟踪。这带来三个后果：

- 主会话上下文里 84% 是机器内容（实测：你说的话 8.4k 字，机器记录 41k 字）；
- 判断错了代价高（丢活、重复建票），判断慢了还要多花一次大模型调用；
- 每一次“接受任务”都是模型在做程序该做的事。

对一个搭档来说，这些都不需要。

## 两层

```
你 ⇄ 对话 agent（DSH 会话，人话 + 工具 + 记忆）
        │ 需要时调用一个工具
        ▼
     任务服务（代码：票、worker、产物、回报）
```

### 对话 agent

- 就是 DSH 的一个普通会话，配记忆、文件、命令、网页工具；
- 它自己回答、自己办小事；
- 只有“要跨天 / 要等 / 要留记录”的事，才调用 `task` 工具开一件任务；
- 它永远是人话的入口。

### 任务服务

- 不再是“受理台”，不是模型，是代码 + 记录；
- 输入只有一个工具调用（标题、说明、可选期限）；
- 负责：建任务、起 worker、重试、跟踪状态、把报告作为**一句人话**送回对话；
- 复用现有引擎里真正有用的部分：票的记录、worker 会话、产物目录、报告。

## 什么退役

| 退役 | 原因 |
|---|---|
| 候选卡 | 消息直接进对话，不再包装 |
| 评估（eval）与规则门 | 单人场景没有治理需求；要不要做由对话 agent 自己判断 |
| mandate / gate | 同上 |
| 多来源排队 | 外部事件变成“叫醒一句话”，由对话 agent 处理 |
| router 预设 | 不再需要“只做路由”的 agent |

## 什么保留

- 票（任务记录）、worker 会话、产物目录、报告页、「存一份」；
- 记忆（全局）、渠道（面板/微信）、dock、压缩提示；
- 定时与素材夹这类“叫醒”。

## 迁移

1. **聊天绕过引擎**：你说的话不再产生 trigger 和候选卡，直接作为对话消息；
2. **加一个 `task` 工具**：对话 agent 用它建任务，引擎被调用而不是自动接单；
3. **报告回对话**：worker 的报告由代码压成一句人话，注入对话；
4. **外部来源后置**：微信/素材夹先保持现状，等前三步验证后再改成“叫醒一句话”。

## 验收指标

- 对话上下文里机器内容占比：现在 84%，目标 **< 10%**；
- 一次日常问答的模型调用次数：现在 2 次以上（router + 可能 worker），目标 **1 次**；
- 一件需要跨天的任务：仍能完成、能问、能等、能看报告。

## 不做

- 不再引入“话题”“项目”“多 router”；
- 不再给模型喂结构化卡片；
- 不为单人场景保留治理层。
